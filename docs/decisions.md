# Decisions (lightweight ADR log)

| # | Date | Decision | Why |
|---|------|----------|-----|
| 1 | 2026-09-25 | **Observer first** (hooks → server), orchestrator later | Works with every existing project immediately; no API key; the visuals can be proven first. |
| 2 | 2026-09-25 | **No Agent SDK**: v2 runner spawns the `claude -p --output-format stream-json` CLI | The user has only the CLI with a browser (subscription) login and no API key. The Agent SDK needs an API key. |
| 3 | 2026-09-25 | **Fastify** modular monolith (plugins + awilix DI + typed event bus) | User rejected NestJS/Express. Payload CMS is Next.js-based and a poor host for socket.io plus long-lived watchers/processes. |
| 4 | 2026-09-25 | **socket.io** for realtime | User requirement; rooms map neatly to project floors. |
| 5 | 2026-09-25 | **SQLite + Drizzle** (better-sqlite3, WAL) | Zero-setup local file; typed schema; can move to Postgres later by swapping the driver. |
| 6 | 2026-09-25 | **Docker compose** delivery, ports on 127.0.0.1 | User choice. Hooks run on the host and reach the published port; `~/.claude/agents` is bind-mounted for role sync; the container runs as the host UID. |
| 7 | 2026-09-25 | Hook = **sh + curl**, always exit 0, no stdout, 1s timeout | Hosts may not have Node on PATH; the hook must never slow down or break Claude Code. |
| 8 | 2026-09-25 | Roles edited in the GUI, **synced** to `~/.claude/agents/*.md` with a managed-by marker | One source of truth; never touch user-authored agent files. |
| 9 | 2026-09-25 | React + **Phaser 3**, procedurally generated map/sprites | No asset licensing or download step; swappable for a Tiled map and sprite pack later. |
| 10 | 2026-09-25 | pnpm workspaces + turbo; `packages/shared` is the contract (zod) | Server and web share types and validation; contract-first lets developers work in parallel. |
| 11 | 2026-09-25 | Security hardening after review: Host/Origin allowlists, 127.0.0.1 bind, GUI-immutable path/network/runner settings, masked token, JSON-only, whole-payload redaction | The security review showed any website could rewrite `~/.claude/agents` through socket.io (CSWSH) and move `agentsDir`. |
| 12 | 2026-09-25 | **No admin token** for the GUI (for now) | With Origin/Host checks, a localhost bind and immutable dangerous settings, browsers and the LAN are excluded, and local processes are already trusted. Revisit when the v2 runner can execute code. |
| 13 | 2026-09-25 | Hook token in `curl.conf` (0600) read via `curl -K`, not sourced shell | Keeps the token out of `ps` and avoids executing a config file on every tool call. |
| 14 | 2026-09-25 | Named Docker volume `office-data` for `/data` | A host bind of `./data` is created by Docker as root when missing, so the non-root server can't open SQLite. |
| 15 | 2026-09-25 | Scripts are `office:up` / `office:down`, not `up` / `down` | `pnpm up` is a built-in alias of `pnpm update` and never runs the script. |
| 20 | 2026-09-25 | Web acks use `emitWithAckTimeout` (manual timer), not socket.io `.timeout().emitWithAck()` | The built-in timeout fired false timeouts through the Vite dev proxy; a denied admin event never acks, so a timeout means "not authorized". |
| 21 | 2026-09-26 | Visual style follows the user's pixel-art references (cozy 3/4 office; castle, tavern and keep for guild), drawn procedurally | References are third-party art: kept outside the repo, used for style only, never traced or committed. |
| 22 | 2026-09-26 | All art is code-drawn, packed into one runtime texture atlas per theme | No asset files. Code-drawn textures are GPU textures once generated, so runtime cost equals sprite sheets; packing them into an atlas cuts draw calls. References are recreated in style, not transcribed pixel for pixel (third-party art). |
| 23 | 2026-09-26 | Quests keep project attribution (only the Receptionist skips it) | A quest is real work in that repo; the README write is opt-in at install and profile imports default to 'ask'. |
| 24 | 2026-09-26 | Pin Docker images to node:24.16-bookworm-slim | node:24 floated to 24.21.0, where better-sqlite3 12.11's Statement destructor hits "Assertion failed: (env) != nullptr" during GC and the server crash-looped (~every 45 s). 24.16 is stable; revisit with better-sqlite3 13.x. |
| 25 | 2026-09-26 | Screen effect (CRT/LCD/VHS) is a per-browser display preference layered over the `office.shaders.screen` server default | Settings writes are admin-gated since v0.3.0; a purely visual preference shouldn't need pairing, and each viewer may want a different look. |
| 26 | 2026-09-26 | Upgraded `better-sqlite3` ^12.2.0 → ^13.0.3 and re-pinned Docker images to `node:24.21.0-bookworm-slim` (unpinning #24's 24.16 freeze) | better-sqlite3 13.0.0 rewrote the native addon on `node-addon-api` (N-API) instead of direct V8/Nan bindings, which is exactly the layer that hit the GC-time "Assertion failed: (env) != nullptr" in #24. drizzle-orm 0.45.3's peer range (`better-sqlite3: >=7`) already covers it, and `pnpm --filter @tagconn/server test` (311 tests) plus root `pnpm typecheck` pass unchanged on host Node 24.16.0. Verified on Docker (throwaway images/containers/volumes, ports 14517, never the live `tagconn-server-1`/`tagconn-web-1`/`office-data` stack): built the server image once with `--build-arg NODE_IMAGE=node:24-bookworm-slim` (resolves to `node:24.21.0-bookworm-slim`, the exact version that crashed in #24) and once with `node:24.16-bookworm-slim` as a control, both against better-sqlite3 13.0.3. Each ran ~3 minutes under `node --expose-gc` with ~73k `/api/hooks` POSTs (real fixtures from `apps/server/test/fixtures`, cycled with fresh `session_id`s) interleaved with ~1k `/api/snapshot` GETs, 12-way concurrency: 0 request errors, 0 restarts, no assertion/abort/OOM in logs on either Node version. Kept `node:24.21.0-bookworm-slim` (an exact patch pin, not the floating `node:24-bookworm-slim`, for reproducibility) since it's the newest verified build. |
| 27 | 2026-09-29 | tagconn Desktop = Tauri 2 shell + a bundled Node sidecar (supervisor) talking JSON-RPC over stdio; native services by default, Docker optional; the desktop registers a Node hook (`office-hook.mjs`) | User choice (Tauri: small, native tray/updater). | 29 | 2026-10-02 | **Half tile is the sub-grid unit** (M15 dual grid): `SUB = 2` cells per tile side (8 px) for rendering, furniture placement and navigation. The dual-grid render is an **additive overlay** on per-tile paint behind `office.dualGrid` (off = byte-identical). The **nav grid** (per-tile nibble masks + true clearance) is the collision source of truth and `GeneratedMap.walkable` is derived from it, conservatively (any blocking overlap blocks the tile). Pin **positions** are multiples of 0.5; **sizes** stay whole tiles until the painter audit. Designs: `docs/design/dual-grid.md`, `docs/design/navigation.md`. | The user asked for denser, more dynamic furniture and smoother movement while keeping the 16 px map grid. One unit for all three layers keeps one constant and one rasterizer; a person is a 2 x 2 block = one tile, so today's behaviour is the `k = 2` special case and every tile consumer (seats, reachability, scripts) keeps its semantics. The 16-bit micro-mask / HPA* / brushfire spec was adapted, not copied: a 4-bit nibble and true clearance are exact for k x k blocks and cheap at 128 x 96. The overlay keeps D2 and the depth invariant and lets the flag fall back to the old look; fractional sizes wait because the furniture painters loop per integer tile. |
| 30 | 2026-10-02 | **Lightmap + host clock + furniture slot identity** (M16). (a) The office follows the **host's** clock: the snapshot carries `clock: { serverNow, tzOffsetMin, tz }`, the client keeps a skew and a stylised `sun.ts` (dawn/dusk smoothstep ramps, east→west skew, no latitude) drives everything; `office.theme` day/night pin the hour, `auto` = `office.lighting.cycle`, a per-browser ☰ slider overrides both (#25 pattern). (b) Night is a **multiplied `RenderTexture` lightmap** at the old overlay depth (90 000), baked only per sun step from pure plans: per-light visibility polygons (angular sweep against style-independent occluders = wall boundaries + furniture with `KIND_HEIGHT ≥ 10 px`, cached per map) drawn as stepped concentric bands, window shafts clipped to the room, a separate furniture shadow `Graphics` at depth -5 and a per-character cast shadow from the dominant light. Procgen guarantees ~1 ceiling light per 24 tiles (`GeneratedMap.lights`). The bloom `LightLayer` (95 000) and the camera post pipelines are untouched; canvas / `low` / `lightmap=false` keep the flat overlay, now sun-driven. (c) Rooms are furnished from **functional groups** with wall/corner/centre affinity, `facing`, clearance and K scored candidates per room (`procgen/harmony.ts`); every recipe item carries a stable **`slotId`** and a pin records **`fromSlot`** (consumes the slot) or **`suppressed`** (deletes it), so dragging a desk never duplicates it; decor positions are per-item hashes; displaced items relocate. `KIND_SHAPE` gets facing-aware insets and painters clip to half-tile sizes, so `w`/`h` become multiples of 0.5 (contract superset, no migration). Designs: `docs/design/lighting.md`, `docs/design/furnishing.md`. | The browser clock made a Docker office in Jakarta go dark on New York time; one measured skew fixes every viewer without a time API. A real solar model has no meaning for windows that are always on the north wall; the stylised sun is one pure function with a table test. Multiply at the existing overlay depth keeps every depth relation, bloom and grading as they are, so M15's dual-grid pass and the back-wall face need no change, and the flat overlay stays as the fallback. Phaser has no radial gradient or polygon clip for render textures, so stepped bands (exact on star-shaped polygons, pixel-art in look) replace a blur pass; polygons are cached because walls are static. Row-packing plus random decor was the root of "wall art mid-floor" and "no facing"; groups with affinities and a scorer give rooms intent while K stays small enough for the +30 % budget. The duplicate-on-drag bug was identity, not geometry: the recipe had no way to know a pin replaced one of its items; a stable slot id is the smallest contract that lets a pin consume (or delete) a slot and survives re-rolls. |
